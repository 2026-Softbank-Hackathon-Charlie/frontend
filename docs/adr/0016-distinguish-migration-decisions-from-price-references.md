# 0016. 이전 추천과 판단 보류의 근거를 첫 줄에서 구분한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

실제 `insufficient` 결과의 일반 비용 확인 문구와 AWS 예시 인스턴스 단가가 이전 추천의 이유처럼 보였다. 앱의 원본·비교 대상은 등록되어 있어도 총비용·용량·데이터 정책이 미확인일 수 있다. 기존 캐시도 배포 직후 남아 있을 수 있다.

## 결정

영역 제목은 ‘AI 이전 판단’으로 표시하고 `move`는 이전 추천, `stay`는 현재 환경 유지, `insufficient`는 판단 보류로 구분한다. 앱·현재 환경·비교 대상을 명확히 표시한다. 미확인 결과는 기존 `missing` 필드의 실제 보류 원인을 먼저 표시한다. 진행 중 이전·국가 제한·출발지 미확인·미등록 대상은 해당 원인을 우선하고, 나머지는 짧은 미확인 항목을 보여준다. 코드가 알려지지 않으면 추가 확인으로 표시하며 가격이나 이익을 추정하지 않는다.

확정된 이전·유지 결과는 서버가 검증한 핵심 비교 이유를 먼저 보여준다. 미확인 결과의 기존 AI 원문과 공식 가격·시장 참고 출처는 접힌 근거에서 확인한다. 참고 단가는 앱 전체 비용이나 실제 인스턴스 종류로 해석하지 않는다. 금액 차이는 `move`에만 표시한다. 오래된 결과의 링크 차단, 정확한 앱·원본·대상 링크, 기존 캐시와 명시적 갱신은 유지한다.

## 검토한 대안

- 이전 추천 제목을 유지하고 일반 참고 단가를 강조: 판단 보류를 이전 이익으로 오해할 수 있어 제외했다.
- 미확인 상황에 더 설득력 있는 이전 이유 생성: 실제 근거가 없어 제외했다.
- 신규 계약 필드 필수화: 기존 캐시·strict AI 소비자와 호환되도록 기존 필드로 해결했다. 서버 후보 근거 변경은 platform ADR 0063에 기록한다.

## 결과

독자는 후보 경로와 실제 판단, 부족한 근거를 바로 구분한다. 한국어·일본어, 키보드·모바일, 갱신 실패·오래된 결과를 검증한다. 테스트 fixture로 재생한 운영 캐시와 실제 운영 AI의 새 결과는 별도 증거로 기록한다.
