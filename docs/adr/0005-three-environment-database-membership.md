# 0005. DB 환경 목록과 관측값으로 세 환경의 역할을 표시한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

플랫폼이 GKE·EKS DB 쌍에 onprem을 추가하지만 콘솔은 생성 당시 primary/replica 두 이름만 DB 역할에 사용하고, 환경 추가도 기존 peer로만 제한했다. onprem으로 이전하면 역할이 빠지거나 생성 당시 역할을 현재 역할로 오해할 수 있다.

## 결정

실제 등록 환경 목록을 표시 대상으로 사용한다. 기존 두 환경이 준비되면 세 번째 환경을 선택할 수 있으며, bootstrap 원본 역할·구성 검사는 서버가 수행한다. 세 환경 그룹의 환경 제거는 서버 계약에 맞춰 차단한다.

세 환경의 DB 역할은 readiness의 관측값으로 표시하고 게이트웨이 트래픽 목적지와 구분한다. DB 관측값이 없으면 역할 미확인으로 표시한다. 기존 두 환경 표시와 peer 미추가 흐름은 유지한다. 생성 primary/peer는 기존 API 앵커로 남기고 멤버 수로 해석하지 않는다.

## 검토한 대안

게이트웨이 writeBackend만으로 DB primary라고 표시하면 역할 변경 중이거나 관측이 실패했을 때 사실과 다를 수 있다. 세 환경에서는 이 추론을 사용하지 않는다. 별도 DB 멤버 API를 추가하는 대신 기존 등록 환경 목록과 readiness를 사용한다.

## 결과

플랫폼의 신규 계획 opt-in 필드를 OpenAPI에서 생성해 동기화한다. 계획 제출은 draft 객체를 그대로 전달하여 추가 필드를 보존한다. 단위·컴포넌트 테스트는 운영 DB 역할이나 실제 클라우드 이전 성공의 증거가 아니며, 브라우저·운영 확인은 별도 수행해야 한다.
