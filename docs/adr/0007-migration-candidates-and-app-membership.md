# 0007. 이전 후보를 표시하되 앱 등록과 DB 준비 여부를 따로 판단한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

이전 대상 목록과 앱 목록의 이전 링크가 `App.environments`에만 의존했다.
이 필드는 DB 이전용 엔드포인트이므로, 플랫폼에 onprem 클러스터가 있어도 앱에
추가되지 않았다면 후보에서 사라졌다. DB가 없는 앱은 `deploy.environments`에
배포 환경이 있어도 이전 링크와 앱 선택 목록에서 사라졌다.

## 결정

대상 후보는 실제 `GET /v1/envs`와 앱 환경 목록의 합집합에서 현재 원본을 제외한다.
클러스터의 이름·상태는 서버 응답을 사용한다. 앱에 등록되지 않은 후보도 고를 수
있지만, 앱 환경 추가가 필요함을 명시하고 기존 앱 상세 화면으로 안내한다.
사용자의 추가 요청 없이 환경을 등록하거나 DB를 전환하지 않는다.

등록 앱의 이전 진입점은 유지하고, 준비가 부족하면 `이전 준비`로 안내한다.
이전 화면에서도 다른 앱으로 조용히 바꾸지 않고 환경·DB 준비가 부족한 이유를 표시한다.
배포 멤버 목록은 DB 엔드포인트의 관측·복제 준비 여부를 대체하지 않는다.

DB가 없는 앱은 앱 spec에 postgres가 없고 DB topology·엔드포인트도 없는 경우로
판별한다. 이 앱의 멤버는 `deploy.environments`에서 읽으며, 실제 관측된 앱별
게이트웨이의 쓰기 대상만 원본으로 삼는다. 게이트웨이를 읽지 못하면 첫 환경을
추정하지 않고 계획 생성을 막는다. DB가 있는 앱은 기존 DB 역할·readiness 계약을
유지하고 DB 이전 엔드포인트가 준비되기 전에는 배포 정보만으로 계획을 허용하지 않는다.

계획 버튼과 AI·수동 계획 handler 모두 미등록 대상·불명확한 원본·준비 부족을
차단한다. 서버의 환경 수, bootstrap DB 원본 역할, 실제 복제·접근 권한 검사도 유지한다.

## 검토한 대안

- onprem 이름을 하드코딩해 무조건 실행 가능하게 추가: 실제 클러스터 존재와
  앱·DB 배포를 구분하지 못하므로 제외했다.
- DB 없는 앱에 가상 CNPG 엔드포인트를 생성: 서버의 `source.kind=none`, `target.kind=none` 계약과
  다르므로 제외했다.
- 이전 버튼을 계속 숨기기: 준비 방법과 미노출 원인을 알 수 없으므로 제외했다.

## 결과

실제 모드 API fixture 테스트로 후보 발견, 미등록 대상 차단, 등록된 대상의
계획 생성, DB 없는 앱의 멤버·원본 판단, 단일 환경 준비 화면과 목록·상세 진입을
확인한다. 이는 실제 클라우드 이전이나 브라우저 검증의 증거가 아니다.
DB 없는 이전에는 platform ADR 0049와 엔진의 `source.kind=none`, `target.kind=none` 지원이 배포돼 있어야
하며, 구버전 서버의 거절은 그대로 사용자에게 표시한다.
