# 0009. 실행 수락 뒤 지도를 열고 실제 단계 결과로 진행 상태를 표시한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

이전 설정과 지도가 처음부터 함께 보여 정보가 중복됐다. AI 실행 응답을 버려 세션 목록 조회가 따라올 때까지 설정 화면이 남았다. 지도 단계는 전체 개수에 비례한 고정 최소 너비와 가로 스크롤을 사용해 좁은 화면에서 단계 이름과 진행 상태를 읽기 어려웠다.

## 결정

- 설정 화면에는 선택 폼, 계획 실행 동작, 실제 준비 경고와 쓰기 기록 설정을 유지하고 지도를 숨긴다. AI 실행의 실제 수락 응답 또는 제출된 Plan 응답을 받은 뒤 지도로 전환한다. 요청 거절은 설정과 오류를 유지한다.
- 수락된 AIRun의 이름으로 조회 결과를 연결한다. 세션 기록이 없으면 기록 대기를 표시하고 조회·복제 활동을 추정하지 않는다. 같은 앱·namespace·요청 방향과 수락 이후 제출 시각이 일치하는 Plan이 도착해야 승인 화면으로 연결한다. AIRun 계약에 planRef가 없어 같은 방향의 동시 요청을 완전히 구분하지는 못한다.
- ADR 0001의 동일 출처 iframe과 명령 검증을 유지한다. 최초 지도 마운트 시점만 설정 이후로 늦추고, AI·승인·실행 사이에는 같은 iframe을 유지한다.
- 단계 카드는 너비에 맞춰 줄을 바꾸고 상태를 글자로 표시한다. 요약은 실제 완료 단계 수, 전체 단계 수, 현재 단계와 실행 상태를 보여 준다. 건너뜀과 판단 보류는 완료 개수에 포함하지 않는다.
- 실행의 완료·실패·멈춤·원복·중단은 서버 상태를 따른다. 실행이 성공했어도 누락된 단계 기록을 성공으로 채우지 않고 시간에 따른 추정 퍼센트를 만들지 않는다.

## 검토한 대안

- 클릭 즉시 지도를 표시: 서버가 거절하거나 네트워크가 실패해도 실행이 시작된 것으로 보인다.
- 세션 목록 조회까지 설정 유지: 실제 수락 후에도 계획 버튼과 설정이 남아 중복된다.
- 경과 시간으로 진행률 표시: 단계별 시간이 일정하지 않아 실제 진행을 증명하지 못한다.
- 고정 너비 가로 진행바 유지: 단계가 많거나 이름이 길 때 전체 상태를 읽기 어렵다.

## 결과

실제 응답을 사용하는 HTTP fixture와 hook 테스트로 수락 전후 화면, 거절 후 재시도, 실패 후 설정 복귀, 목록 지연, 다른 방향 Plan 차단을 확인한다. 지도 렌더러는 DOM 테스트로 단계 상태와 요약을 확인한다. 실제 브라우저와 운영 이전은 이 변경에서 검증하지 않았다.
