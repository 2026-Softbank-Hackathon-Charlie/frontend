# 0002. 이전 지도 상세 보기에서 검증 목적과 수신된 판정 근거를 분리한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

지도의 상세 보기는 단계 이름만 확장하고 동등성·레지던시 검증의 목적과 결과를 별도로 설명하지 않았다. 프론트엔드는 시작 요청 감사 기록에서 레지던시 결과를 받지만 현재 MigrationView에는 동등성 결과가 없다.

## 결정

상세 버튼을 누르면 지도 위에 두 검증 카드를 표시한다. 목적·검사 항목·판정·근거를 나누고 좁은 화면에서는 한 열로 배치한다. 기존 스냅샷에 validations를 추가하고 iframe이 textContent로 렌더링한다. 기존 스냅샷에 필드가 없으면 빈 카드 영역으로 처리한다.

레지던시는 기존 preflight의 상태·요약·이유·시각·정책 digest를 그대로 사용한다. 미수신·미검사·불명·차단을 허용과 구분한다. 동등성은 검사 범위를 설명하되 결과 미수신으로 표시한다. 완료된 이전과 리허설 성공에서 판정을 추론하지 않는다. API 호출과 시작 차단 동작은 변경하지 않는다.

## 검토한 대안

- 하나의 시작 전 검사 표에 합치기: 목적 차이가 잘 드러나지 않아 독립 카드로 나눈다.
- 이전 성공을 동등성 통과로 표시하기: 실제 근거가 없어 채택하지 않는다.
- 동등성 결과 API 연동까지 확장하기: 이번 설명 가독성 개선과 분리한다.

## 결과

현재 판정 근거가 없는 항목도 검사 목적과 한계를 볼 수 있다. 실제 동등성 판정 표시는 후속 연동이 필요하다. UI 단위 테스트는 상세 토글과 상태 매핑을 확인하며, 실제 운영 검증을 대신하지 않는다.
