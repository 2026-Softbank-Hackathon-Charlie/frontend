# 0015. AI 활동과 지도는 연결된 메타데이터로 앱·환경·DB 의존성을 표시한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

AI 활동에는 앱과 이동 경로가 없어 어떤 작업인지 비교하기 어렵고, 지도는 DB가 없는 앱에도 CNPG와 DB 연결을 그렸다. 제목이나 앱 이름 문자열로 맥락을 추정하거나 조회 실패를 DB 없음으로 처리하면 실제 기록과 다른 정보를 표시한다.

## 결정

AI 활동에 앱·From·To 세 컬럼을 추가한다. 세션의 정확한 runId/planRef로 목록의 실행·계획을 연결한다. `Run.app` 또는 `PlanSummary.app`이 있으면 사용하고, DB 앱은 양쪽 환경·namespace·CNPG 이름이 등록 앱의 두 endpoint와 일치하며 유일할 때만 앱명을 표시한다. 이름·제목·planId를 해석하지 않는다. 연결되지 않거나 앱이 모호하면 미확인이다. 실행·계획 ref가 충돌하면 맥락을 섞지 않는다.

목록 데이터는 페이지에서 한 번 읽어 모든 행과 변하지 않은 세션 응답에 재사용한다. 새 ref가 관측되거나 사용자가 실패한 조회를 다시 요청할 때 갱신한다. 세션별 조회를 추가하지 않는다. 목록 조회 실패는 미확인과 별도로 표시하며 기존에 읽은 값은 유지한다. Plan 생성 전이나 ref 없는 세션은 서버 계약의 맥락 필드가 없어 미확인으로 남는다. 생산자 필드 추가는 별도 후속 작업이다.

지도 snapshot은 DB 존재를 present/none/unknown으로 구분한다. 실행 중 endpoint의 명시적 DB 의존성이 현재 앱 명세보다 우선한다. source와 target이 모두 `kind=none`이거나 유효한 등록 명세상 postgres·DB topology·CNPG 의존성이 없을 때만 none이다. 파일 이전 유무와는 별개다. 데이터가 없거나 불완전하면 unknown이며 DB를 제거하지 않는다. 공개 PlanEndpoint·PlanSummary와 Run의 비밀 없는 메타데이터만 canonical OpenAPI에서 공식 생성기로 추출한다.

none인 지도는 DB 노드, 앱→DB 연결, DB 요청·복제·교차 쓰기 경로를 생성하지 않는다. 사용자→클러스터→앱 트래픽은 앱으로 연결하고, 파일 전용 이전은 파일 경로·입자를 유지한다. 앱 AI 카드와 추론 경로는 유지한다. DB/파일 유무가 바뀌면 같은 이전 경로에서도 지도를 다시 구성해 이전 경로의 입자를 제거한다.

환경의 DB/백업은 문장 대신 DB별 짧은 준비 수·역할·백업 상태·최근 성공·복구 가능 시작 시각을 표시한다. CNPG 목록의 누락과 빈 배열을 구분한다. namespace는 전체 tooltip에 보존하며 같은 이름의 DB가 중복되면 표시 이름에도 포함한다. 앱 요약 부연과 개요 소개 삭제·데모 전환 텍스트 버튼·좌측 로고 12.5% 확대는 상태·필터·권한을 바꾸지 않는 표시 조정이다.

## 검토한 대안

- 제목에서 앱·환경을 추출: 임의 제목과 재시도에 따라 잘못 연결할 수 있어 제외했다.
- 모든 행의 상세를 주기적으로 조회: 중복 요청이 증가하므로 목록 재사용과 ref 변경 시 갱신을 선택했다.
- DB 노드를 숨기기만 하기: 연결과 입자가 남으므로 노드와 관련 경로를 생성하지 않는다.

## 결과

순수 계약 검사와 실제 React/API hook·지도 DOM 회귀로 정확한 연결, 미연결·중복·충돌·조회 실패, metadata 재사용, DB 없는 앱·파일 전용 이전·DB 있는 앱·unknown의 경계를 확인한다. 임의의 실제 앱 호출·이전·AI 실행은 하지 않는다. 브라우저 도구가 없어 모바일 시각 검증과 운영 데이터의 실제 표시를 확인했다고 보고하지 않는다.
