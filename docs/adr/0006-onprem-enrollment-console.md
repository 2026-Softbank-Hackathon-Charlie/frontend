# 0006. 온프렘 연결 코드는 서버에서 발급하고 실제 점검 결과로 완료를 판정한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

환경 화면은 이미 등록된 클러스터를 조회한다. 사용자가 자기 장비를 연결하려면
등록 코드, Linux/WSL2 설치 명령, 만료와 연결 점검 결과를 볼 수 있어야 한다.
브라우저에서 임의 코드를 만들거나 기존 onprem의 정상 상태를 새 연결 성공으로
표시하면 실제로 동작하지 않는 등록 흐름을 성공으로 보이게 한다.

## 결정

실제 모드의 환경 화면에 온프렘 연결 패널을 추가한다. 관리자만 코드 발급·폐기를
요청한다. 서버는 권한과 이름 충돌을 검사하고 짧은 수명의 일회용 코드를 발급한다.
설치 명령은 서버가 반환한 문자열만 표시·복사하며 브라우저가 명령을 실행하지 않는다.
기존 k3s는 재사용하고 없는 k3s 설치는 별도의 동의 값으로 서버에 전달한다.

발급 계약은 `POST /v1/onprem/enrollments`, 조회는 `GET /v1/onprem/enrollments/{id}`,
폐기는 `POST /v1/onprem/enrollments/{id}/revoke`다. 발급 응답만
`enrollment`, `code`, `installCommand`를 포함하고 조회·폐기는 코드 없는 상태를 반환한다.
브라우저는 코드와 명령을 React 메모리에만 보관한다. 사용·만료·폐기되거나 최신 상태를
읽지 못하면 명령을 숨긴다. 새 코드 발급 전에는 남아 있는 요청의 폐기가 성공해야 한다.
발급 요청을 자동 재시도하지 않는다. 발급 응답을 잃은 경우 서버의 중복 요청 계약이
필요하며 클라이언트가 잃은 코드를 추정하거나 생성하지 않는다.

서버 상태가 `ready`이고 k3s·네트워크·권한·이미지 다운로드·Hello World 다섯 점검이
모두 `passed`일 때만 배포 준비 완료로 표시한다. 빠진 점검은 미확인이다. UI에서
환경 활성화 명령을 실행하거나 기존 환경의 조회 결과로 등록 점검을 대체하지 않는다.

## 검토한 대안

- 프론트에서 코드·설치 명령 생성: 토큰의 실제 검증·폐기 및 서버 등록과 연결되지
  않으므로 선택하지 않는다.
- 기존 클러스터의 reachable 값으로 완료: 이미지 다운로드·배포 권한·HTTP 응답을
  증명하지 못하므로 선택하지 않는다.
- 장기 kubeconfig를 브라우저에서 붙여넣기: 자격정보 노출 범위가 커져 선택하지 않는다.

## 결과

이 PR은 실제 API 응답을 소비하는 콘솔을 제공한다. 서버의 발급·claim·설치 프로그램과
등록 작업자는 별도 구현 및 배포가 필요하다. API가 없는 구버전 서버에서는 지원하지
않음을 표시하며 코드·명령이나 성공 상태를 만들어내지 않는다. 컴포넌트 테스트는
API fixture로 계약을 확인하며 실제 장비 설치·클라우드 배포의 성공 증거는 아니다.
현재 세션에 실제 브라우저 도구가 없어 브라우저 검증은 수행하지 못했다.
