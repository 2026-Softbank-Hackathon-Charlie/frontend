# 0014. 개요의 이전 추천은 AI 결과와 서버 갱신 제한을 따른다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

부하와 비용이 변할 때 앱을 어디로 옮길지 빠르게 살피고 싶지만, 상시 AI 호출이나 미확인 비용을 절감액처럼 표시하면 판단을 흐린다. 화면에서 선택한 환경은 이후 바뀔 수도 있다.

## 결정

실제 개요의 ‘지금 볼 것’에서 서버의 `/v1/migration-recommendations` 결과만 표시한다. 공개 API 스키마에서 두 viewer 경로와 재귀 참조 타입을 공식 생성기로 추출하며, 임의의 AI 응답을 화면에서 생성하지 않는다. 생성 중·미연결·실패를 구분하고 결과가 없으면 이전 추천을 채워 넣지 않는다. 앱과 현재·대상 환경, 두 개 이하 이유를 표시하며 미확인 금액은 생략한다. 공식 출처와 확인 시각, 누락 조건, 모델은 접어서 확인한다.

화면 진입과 수동 새로고침만 요청하며 로그인 세션별로 캐시하고 동시 호출을 합친다. 서버 `nextRefreshAt`을 갱신 제한으로 사용한다. 생성 중에는 `nextCheckAt` 이후 수동 확인으로 읽기 전용 `/status`를 요청한다. 타이머는 버튼을 활성화할 뿐 네트워크를 호출하지 않는다. 마지막 사용자가 화면을 떠나면 진행 중 요청을 중단한다. 실패는 최소 60초 또는 서버 재시도 간격으로 제한하며 오래된 결과에서는 이전 링크를 숨긴다.

이전 링크는 앱·원본·대상을 포함한다. 이전 화면은 현재 게이트웨이에서 확인한 원본과 등록된 대상이 일치할 때만 대상을 미리 선택한다. 원본이 바뀌거나 대상이 미등록이면 경고하고 기존 준비·계획·리허설·승인 절차를 그대로 적용한다. 추천 링크가 실행 요청을 보내지는 않는다.

## 검증과 한계

React/DOM 검사로 세션 분리, 진입 캐시, 중복 클릭, 네트워크 폴링 부재, 수동 결과 확인, 중단, 오류·404 대응 및 대상 선택을 확인한다. 실제 AI 추론과 비용·배치 근거의 수집·필터링은 플랫폼 및 AI 샌드박스 계약의 책임이다. 브라우저 도구가 없는 환경에서 실제 모바일 화면 검증이나 운영 AI 연결을 확인했다고 보고하지 않는다.
