# 0008. 신규 장비 이름 충돌과 실제 연결 완료 범위를 콘솔에서 구분한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

실제 온프렘 등록 작업자가 추가되면서 기존 `onprem` 이름을 새 장비에 재사용하면
이미 등록된 클러스터를 교체한다고 오해할 수 있다. 서버 설정 미완료인 503도
구버전 미지원과 다르며, 설치 명령을 실행한 것과 서버의 등록 검사가 끝난 것은 다르다.

## 결정

환경 화면이 실제 `GET /v1/envs`에서 읽은 이름을 연결 패널에 전달한다. 이름 목록을
읽지 못했거나 기존 이름과 같으면 신규 코드 발급을 막는다. 기존 onprem이 있으면
입력을 비우고 새 장비용 이름을 요구한다. 서버의 환경 소유권·덮어쓰기 금지 검사를
대체하지 않으며, 조회와 등록 사이에 생기는 충돌도 서버 오류로 표시한다.

`enrollment_issuer_unavailable`은 등록 서비스 설정 미완료로 설명하고 명시적 재시도를
허용한다. 구버전의 404·405·501 미지원은 기존대로 구분한다. 기존 멱등 발급 키와
코드 재조회·폐기 동작을 유지한다.

서버의 optional `stage`를 사용자용 문구로 표시한다. 구버전의 필드 생략이나 새 단계가
등장했다고 진행률·성공을 추정하지 않는다. `ready`와 다섯 필수 검사 통과 조건을
유지하되, 완료 범위를 Kubernetes 연결·제한된 Hello World 검사로 명시한다.
DB·MinIO·GPU 설치와 환경 동등성 검증 완료를 뜻하지 않는다.

설치 명령의 Linux/WSL2 Linux·root·curl·python3·sha256sum 전제조건과 k3s 신규 설치에
필요한 systemd/OpenRC를 안내한다. 명령은 기존 k3s 재사용 또는 동의한 설치 후 연결
서비스를 설치하고 서버 검증을 기다린다. 장기 관리자 kubeconfig 대신 연결 서비스가
짧은 서비스 계정 토큰을 갱신한다는 현재 설치 프로그램의 동작을 안내한다.

## 결과

API fixture·컴포넌트 테스트로 이름 충돌, 설정 오류·재시도, 구버전 호환, 실제 단계와
불명확한 단계, 완료 범위를 확인한다. 이 변경 자체는 클러스터·자격증명·연결 서비스를
배포하지 않는다. 실제 장비 설치와 브라우저 검증은 별도의 증거가 필요하다.
