# 0001. 이주 지도는 콘솔 상태를 받아 그리는 같은 출처 iframe 하나로 계획부터 실행까지 보여 준다

- 상태: 채택
- 날짜: 2026-11-05

## 상황

디자인 핸드오프(`hopcharlie-migration-map-handoff/migration-map.html`)의 이주 지도는 입자 애니메이션,
파이프 흐름, 단계 표시를 가진 단독 HTML이지만, 안에 자체 시뮬레이터(`simulate`, `scripts`)가 있어
고정된 지표와 대본 로그를 보여 준다. 처음에는 데모 모드에서 원본을 그대로 iframe으로 넣었는데, 그러면
콘솔 시뮬레이션과 지도 시뮬레이션이 따로 돌아 승인이 두 번 있고 상태가 서로 맞지 않았다.
지도는 AI 계획, 샌드박스 리허설, 승인, 실행까지 실제 상태를 따라 이어져야 한다(finals-constraints: No Mock).

## 결정

- `public/migration-map-live.html`: 핸드오프의 스타일, 지오메트리, 입자 루프를 유지하고 시뮬레이터를 뺀 렌더러.
  `render(snapshot)`만 하고 스스로 상태를 만들지 않는다.
- `src/data/mapSnapshot.ts`의 `buildMapSnapshot(MigrationView, ctx)`가 콘솔의 상태(데모는 콘솔 시뮬레이션,
  일반 모드는 Plan, AI 세션, run SSE, 게이트웨이 트래픽)에서 지도가 그릴 값을 만든다. 모르는 값은
  비워 두고(`share` 미정, "트래픽 미수신") 0으로 채우지 않는다. halted는 롤백으로 그리지 않는다.
- 부모와 iframe은 `postMessage`로만 주고받는다: `hc-snapshot`(부모→지도), `hc-ready`, `hc-height`,
  `hc-cmd`(지도→부모). 양쪽 모두 같은 출처와 상대 창을 확인한다.
- 지도 버튼(`hc-cmd`)은 그 순간 스냅샷이 제시한 동작이고 `busy`가 아닐 때만, 다음 스냅샷이 올 때까지
  한 번만 실행한다. 실제 권한 검사는 여전히 백엔드가 한다.
- 지도 아래의 전환 카드, 진행 단계 카드, 트래픽 카드는 지도와 중복이라 없앴다. 페이지는 지도 요소를
  같은 key로 유지해 설정 화면에서 실행 끝까지 iframe이 다시 로드되지 않는다.
- 입자는 OS의 움직임 줄이기 설정을 기본으로 따르되, 지도 안의 "움직임 켜기/끄기"로 보는 사람이 바꿀 수 있다.

## 검토한 대안

- 원본 HTML을 시뮬레이터째 데모에만 넣기: 원본과 똑같아 보이지만 콘솔 상태와 따로 놀고, 데모 화면에 대본 결과가 남는다.
- React/SVG로 전부 다시 구현하기: 상태 연결은 쉽지만 두 번 시도해 원본의 모양과 움직임을 맞추지 못했다.
- iframe 대신 원본 스크립트를 페이지에 직접 넣기: 전역 스타일과 DOM id가 콘솔과 충돌한다.

## 결과

- 데모 모드에서 Chrome(1280px, 움직임 허용)으로 설정 → AI 계획(주황 조회 입자) → 리허설 → 지도 안 승인 →
  초기 복사(초록 행·파일 입자) → 전환 → 완료까지 같은 iframe에서 이어지고 콘솔 오류가 없음을 확인했다.
- 일반 모드는 단위 테스트(fixture)로만 확인했다. 실제 플랫폼의 SSE, 게이트웨이 트래픽으로 지도가 맞게 움직이는지는 아직 확인하지 않았다.
- 일반 모드에서 AI 세션 이벤트는 선택된 한 세션 것만 받으므로, 지도의 이벤트 패널에는 그 세션의 로그만 나온다.
- 종료된 과거 run을 볼 때 게이트웨이의 현재 트래픽이 섞일 수 있다(현재 상태이지 그 시점의 기록은 아니다).
