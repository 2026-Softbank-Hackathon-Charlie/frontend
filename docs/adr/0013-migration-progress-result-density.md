# 0013. 이전 진행은 실제 큰 단계 원으로, 결과는 핵심 지표와 개별 상세 접기로 표시한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

이전 페이지는 지도 위 4단계 안내와 지도 안 진행 표시가 중복되고, 요약 카드가 커서 실제 진행 지도를 밀어냈다. 결과 목록도 쓰기 기록·판단 근거를 모두 펼쳐 여러 실행을 비교하기 어려웠다.

## 결정

지도 밖의 AI 계획·리허설·승인·실행 안내만 제거한다. 기존 설정 화면, 승인 버튼과 iframe 명령 검증은 유지한다. 요약 4개는 간격과 글자 크기를 줄이되 실제 수치와 미측정 상태를 생략하지 않는다.

지도 진행은 기존 snapshot의 `phases.group`과 순서를 사용하는 큰 단계 원, 연결 화살표, 원 아래의 실제 내부 단계·완료 수로 표현한다. 시간으로 계산한 진행률은 만들지 않는다. 현재 실행/승인 대기 원에만 배경 맥동을 적용하고, 종료·실패·연결 끊김에서는 멈춘다. OS 동작 줄이기와 기존 움직임 설정을 존중한다. 상세 검증을 펼쳐도 큰 단계 위치는 유지한다. 좁은 화면은 원을 작게 눌러 겹치게 하지 않고 진행 영역 안에서 가로 탐색한다.

결과 카드의 기본 정보는 앱·경로·상태·시각/run ID와 6개 지표다. 쓰기 기록, 실패 설명, 전환 판단, 엔진 단계는 하단 버튼으로 실행별로 펼친다. 미측정·누락·실패 요청은 기본 지표에 남기고, 쓰기 검증 오류나 전환 후 관찰 위반도 작은 상태 표시에 남긴다. 실행 키와 React 상태를 사용해 주기적 데이터 갱신이 펼침 상태를 초기화하지 않게 한다. 버튼은 `aria-expanded`, `aria-controls`와 키보드 기본 동작을 갖는다.

## 검토한 대안

- 기존 막대 여러 개를 더 작게 줄이기: 큰 단계와 내부 단계를 동시에 읽는 문제를 해결하지 못한다.
- 모든 상세를 제거하기: 미측정 원인과 실패 판단을 확인할 수 없으므로 제외했다.
- 업데이트마다 원을 자동으로 넘기기: 실제 엔진 기록과 다른 진행을 만들 수 있어 제외했다.

## 결과

진행 표시의 상태 계약과 이전 API는 바뀌지 않는다. DOM 렌더러 회귀로 실제 snapshot의 진행·대기·종료·연결 끊김, 명령 브리지 회귀로 기존 허용 경계를 검증한다. 결과는 기본 지표·독립 펼침·새 응답 유지·키보드 동작을 검증한다. 브라우저 도구가 없어 실제 화면의 시각적 배치와 모바일 터치 검증은 별도로 남는다.
