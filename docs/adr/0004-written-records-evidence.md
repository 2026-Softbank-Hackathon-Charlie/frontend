# 0004. 쓰기 기록 수집과 검증 결과를 측정 범위에 맞게 표시한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

이전 결과의 missingWrites가 없으면 미측정으로 표시하는 동작은 맞지만, 수집 연결이 없는지,
기록이 없는지, 검증 단계에 도달하지 않았는지 구분할 정보가 없었다. 또한 이전 완료 리포트는
모든 기록을 k6의 성공 응답으로 설명해 앱 DB 커밋 기록과 구분하지 못했다.

## 결정

플랫폼의 RunResult.writeVerification을 사용해 미연결·수집 0건·검증 미실행·검증 완료·오류를
구분한다. 검증 입력이 비어 있으면 누락 0건으로 보여주지 않는다. measured 상태에 양수 checked와
유효한 missing이 있어야 측정값을 표시한다. 오류의 부분 누락 결과는 별도로 표시하며 기존
missingWrites만 있는 응답은 과거 형식임을 명시하고 값을 보존한다.

실행별 collectedRecords/latestAt은 검증 직전에 동결된 입력이다. 과거 실행에 현재 스트림 통계를
덧붙이지 않는다. 이전 설정 화면에서는 app-<App.name> 기본 스트림의 count/latestAt을 실제 API로
조회하되 현재 전체 스트림 정보임을 구분하고, heartbeat가 없으므로 수집기 정상 동작 중이라고
표시하지 않는다. 기본 스트림이 63자를 넘는 앱은 조회하지 않으며 명시적 스트림 사용을 안내한다.

application_commits는 앱 DB 커밋 증거이고 클라이언트의 성공 응답 수신을 증명하지 않는다.
reservation_inserts는 예약 생성만 포함하며 수정·삭제·다른 쓰기를 포함하지 않는다. 보고된 범위에서
누락이 0이라는 사실을 모든 사용자 요청의 무손실 보장으로 확대하지 않는다. 제공자 원본 오류나
알 수 없는 reason 문자열을 그대로 표시하지 않는다.

## 검토한 대안

- 미측정 값을 0으로 대체: 입력 없는 실행을 검증 성공처럼 보여주므로 제외한다.
- 종료 실행마다 현재 스트림 조회: 당시 검증 입력과 이후 수집을 섞고 요청 수를 늘리므로 제외한다.
- 모든 기록을 성공 응답 기록으로 설명: 실제 앱 DB 커밋과 수신 확인의 차이를 숨기므로 제외한다.

## 결과

컴포넌트·이전 결과 테스트는 미측정/0건 구분, 검증 상태 갱신, 실패 부분 결과, scope/coverage와
기존 응답 호환을 검증한다. 수집 조회는 오류·재시도·앱 전환 시 정보 분리를 검증한다.
테스트 fixture는 운영 성공 증거가 아니다. 이 변경만으로 과거 미측정 실행을 소급 검증하지 않는다.

현재 frontend main의 생성 schema에는 platform main보다 앞선 앱 환경 관리 계약이 포함되어 있다.
전체 재생성은 그 계약을 제거하므로 backend OpenAPI에서 생성된 WriteVerification, RunResult의
새 optional 필드와 WrittenRecord/WrittenRecordsRequest/WrittenRecordStats 추가분만 반영한다. 새로운 부분은 backend 생성 결과와
비교하고 기존 계약은 유지한다.

운영 배포와 실제 브라우저 검증 여부는 PR의 검증 결과에 따로 기록한다.
