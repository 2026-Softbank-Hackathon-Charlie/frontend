# 0012. 앱 AI 서비스의 실행 위치와 관측된 호출을 별도로 그린다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

기존 지도는 플랫폼 에이전트 hopai의 계획·리허설을 표시하지만, 이전 중인 앱이 사용하는 모델의 실행 위치는 표시하지 않았다. 호출하는 앱이 온프레미스에 있어도 모델은 Bedrock이나 외부 API에 있을 수 있다. 모델 이름이나 호출 URL만으로 GPU와 실행 위치를 확정할 수 없다.

## 결정

앱별 `/v1/apps/{app}/ai-services?minutes=5` 응답을 읽어 호출 환경과 모델의 실행 위치를 분리한다. self_hosted이면서 GPU 증거가 있는 경우만 GPU 아이콘을 사용한다. 관리형 AI는 별도 아이콘으로 제공자 환경 안에, 외부 API와 실행 위치 미확인은 클러스터 상자 밖에 배치한다. 기존 hopai 경로는 앱 추론 경로와 구분한다.

호출 환경별 route ID와 물리 서비스 ID를 분리해 하나의 모델을 여러 환경에서 호출하는 경로를 보존한다. 서비스 위치의 관측이 충돌하면 위치 미확인으로 표시한다. 실제 수집 창 안에 있고 최근 90초 내 발생한 양수 호출만 토끼를 표시하며, 조회 실패·미관측·유휴·미래 시각에는 토끼를 표시하지 않는다. 토끼의 움직임은 최근 호출 관측의 기호이며 실제 RPS 재현이 아니다.

배치별 시각적 카드는 최대 네 개이며 초과 서비스는 명시적 집계 카드로 묶는다. 전체 물리 서비스·호출 환경·검사 시각·근거는 별도 목록에 모두 유지한다. 동적 텍스트는 SVG/HTML textContent로 렌더링하며 원시 로그나 자격증명을 지도 계약에 추가하지 않는다.

## 검토한 대안

- 모델 이름이나 앱의 이전 방향으로 실행 위치를 추정하면 외부 API와 관리형 서비스의 위치를 잘못 표시한다.
- 설정된 서비스에 항상 트래픽을 그리면 관측되지 않은 호출을 실제 요청처럼 표현한다.
- 모든 서비스를 하나의 'AI' 노드로 합치면 실제 외부 호출과 데이터 이동 경계를 구분할 수 없다.

## 결과

플랫폼 에이전트와 앱 AI 의존성을 분리하며, 관리형·직접 실행·외부 API와 미확인을 구분한다. backend 계측이 없는 앱은 미관측으로 남기며 AI를 사용하지 않는다고 단정하지 않는다. DOM 기반 렌더러 회귀는 실제 브라우저의 레이아웃과 화면 성능을 증명하지 않는다. 실제 서비스 배치·트래픽은 운영 관측 데이터가 수집되어야 확인할 수 있다.
