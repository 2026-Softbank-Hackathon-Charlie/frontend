# 0003. 원본 정리 상태와 보존 조작은 서버 예약을 기준으로 표시한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

플랫폼에 보존 기간 이후 원본 DB를 정리하는 수명주기가 추가됐다. 화면에서 시간을 세어 임의로 삭제 완료나 롤백 가능 여부를 표시하면 실제 서버 상태와 달라질 수 있다.

## 결정

라이브 모드의 종료된 실행에만 정리 패널을 표시하고 `GET /v1/migrations/{runId}/retention`을 15초마다 읽는다. 신규 실행 ID에는 이전 실행의 응답을 보여주지 않는 기존 polling hook을 사용한다. 예약 없음·대기·예약·보류·삭제 중·완료·취소를 구분한다.

운영자에게만 24시간 연장과 계속 보존을 제공한다. 버튼은 POST 요청과 연결하며 처리 중 중복 제출과 상태 갱신 오류 중 조작을 막는다. 서버는 role·동시 실행·기한 단축 금지·삭제 시작 여부를 다시 검사한다. 브라우저에서 삭제를 실행하거나 예약을 새로 만들지 않는다.

기한이 지나도 안전 조건에 따라 삭제가 보류될 수 있고, 삭제가 시작되면 즉시 역방향 롤백이 불가능함을 표시한다. PVC와 공유 Kubernetes 클러스터는 자동 삭제 대상이 아님을 명시한다. 조회 실패는 성공으로 바꾸지 않으며 마지막 응답이 있으면 오래된 상태임을 표시한다.

## 검토한 대안

- 이전 성공 시 고정 24시간 카운트다운: 실제 서버 정책과 재시작 상태를 반영하지 못해 기각한다.
- 클라이언트 timer로 정리 요청: 브라우저 종료 시 중단되므로 서버 수명주기로 처리한다.
- 화면에서 즉시 삭제: 이번 API는 보존을 늘리거나 취소만 허용한다.

## 결과

기존 시뮬레이션에 가짜 삭제 결과를 넣지 않는다. 백엔드 retention API가 먼저 배포돼야 하며 미지원 서버의 오류는 숨기지 않는다. 실제 브라우저 도구가 연결되지 않아 시각·모바일·키보드 검증은 미실시이고 DOM/상호작용 테스트로 확인한 범위를 구분한다. 운영 환경에서의 자동 삭제와 독립 복구 파이프라인 검증은 플랫폼 ADR 0035의 범위다.
